# ADR-0003: Use pnpm 12 instead of pnpm 10

- Status: Accepted
- Date: 2026-10-16
- Deciders: @Laaloz

## Context

ADR-0001 pinned pnpm 10.34.7 because Vercel's documentation lists pnpm 6–10 as supported without the experimental Corepack flag. The owner's machine runs pnpm 12.11.2, and `packageManager` was bumped to it in 93f41ac. pnpm 12 also refuses to install until each dependency build script is explicitly allowed or denied (`allowBuilds`), which is how `esbuild` and `unrs-resolver` surfaced on the first install. Vercel's package-manager documentation (checked 2026-10-16) still names pnpm 6–10 and says nothing about 11 or 12. Nothing is deployed yet.

## Decision

- Use pnpm 12 (pinned in `packageManager`) locally and in CI (`pnpm/action-setup` reads the pinned version).
- Deny install scripts for `esbuild` and `unrs-resolver` with `allowBuilds: false`. Both ship prebuilt binaries as optional platform packages, so no script is needed. `strictDepBuilds`, `minimumReleaseAge`, `trustPolicy` and `blockExoticSubdeps` are unchanged. Any future `allowBuilds: true` entry needs a stated reason in the pull request.
- On Vercel, set `ENABLE_EXPERIMENTAL_COREPACK=1` in both projects so that the `packageManager` field is honoured. Verify this in the first deployment. If it fails, fall back to pnpm 10.34.7 and supersede this ADR.
- Node stays at 24 LTS in `.nvmrc` and CI. Newer local Node versions work, but only 22.12+ and 24 are supported.

## Alternatives considered

- **Stay on pnpm 10.34.7:** matches Vercel's documented support, but the owner's toolchain and lockfile already moved to 12, and a downgrade would be a second migration later.
- **Let Vercel infer the version from the lockfile:** it would pick pnpm 10 and could not read a pnpm 12 lockfile.

## Consequences

- Both Vercel projects depend on an experimental Corepack flag until Vercel documents pnpm 12 support.
- The supply-chain rules from ADR-0001 stay in force; only the pnpm version and the build-script syntax changed.
- Revisit when Vercel lists pnpm 12 as supported (then the Corepack flag can be removed).
